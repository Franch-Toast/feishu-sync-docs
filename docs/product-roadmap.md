# 产品需求规划（PM 视角）

基于对代码现状、README 描述与测试覆盖的完整审阅，以下为尚未实现或明显不足的用户需求，按优先级与主题分组。

---

## P0 — 影响核心体验的缺口

### 1. 外部通知渠道未接入

**现状**：`Notifier` 接口已预留，但默认实现是 `NoopNotifier`，冲突、失败、凭证失效三类事件**只在应用内展示**，用户必须主动打开浏览器才能感知。

**用户价值**：长时间运行后用户不再盯着页面，冲突/认证失效若不能及时感知，会积累大量待处理任务，降低信任感。

**建议实现**：
- 优先接入飞书自定义机器人 Webhook（`FeishuWebhookNotifier` 骨架已在 `notify.ts` 注释中）；
- 设置页增加 Webhook URL 配置项与测试发送按钮；
- 通知策略：每类事件独立开关（`NotificationPreferences` 类型已定义），支持免打扰时段；
- 后续可扩展：系统桌面通知（Web Push）、企业微信、钉钉。

---

### 2. 知识库（Wiki）同步不支持

**现状**：`openapi.ts:listTree()` 明确抛出 "Wiki roots are not supported"；`remoteType` 字段已预留 `"wiki"` 但实际无法使用。

**用户价值**：飞书知识库是团队文档的主要载体，不支持 wiki 会让大量用户无法落地。

**建议实现**：
- 实现 `FeishuWikiProvider`，封装 `wiki/v2/spaces`、`wiki/v2/nodes` 接口；
- wiki 节点的 `obj_token` ↔ `node_token` 双层映射需要专门处理；
- 绑定表单增加「知识库空间」类型选项；
- 注意：wiki 空间的目录结构由知识库管理员维护，同步时应只读目录结构、可读写文档内容。

---

### 3. 缺少主动健康告知（凭证即将过期）

**现状**：user_access_token 通过 refresh token 自动续期，但 refresh token 本身约 7 天过期（若服务连续 7 天未运行则失效），目前只在 token 已经失效后才通过 `auth-invalid` 告知。

**用户价值**：用户出差/服务停机后回来发现所有同步都中断，体验差。

**建议实现**：
- `maintainCredentials()` 在续期 token 时检测 refresh token 剩余有效期；
- 低于 48h 时通过 Notifier + 顶栏徽章提示「请在 X 天内重新授权」；
- 设置页增加「Token 有效期」倒计时展示。

---

## P1 — 重要功能增强

### 4. 选择性同步（文件级开关）

**现状**：`exclude` 模式只支持 glob 路径，粒度较粗；条目级别的 `ignoredAt` 是通过「忽略」入口设置的，但没有文件树直接开关。

**用户价值**：某些子目录或临时文件不希望参与同步，但在 UI 中一键切换比配置 glob 更直观。

**建议实现**：
- DocsView 文件树每行增加「暂停同步」切换按钮（icon toggle）；
- 点击后设置 `ignoredAt`，恢复时清空，无需重启；
- 支持右键多选批量操作；
- 被忽略的文件在树中显示灰色半透明状态，附带「忽略原因」tooltip。

---

### 5. 文档全文搜索

**现状**：DocsView 只支持文件名过滤（`relativePath` 搜索），无法搜索文档内容。

**用户价值**：用户通常记得内容关键词而非文件名，内容搜索是文档管理的基本需求。

**建议实现**：
- 服务端：对 Markdown 文件内容建简单倒排索引（可懒触发，scan 结束后增量更新）；
- 新增 API：`GET /api/roots/:id/search?q=keyword` 返回匹配的 entryId + 摘要片段；
- 前端：顶栏全局搜索框，结果列表点击跳转至文档预览并高亮关键词；
- 无需引入 Elasticsearch 等重型方案，SQLite FTS5 或 `minisearch` 内存索引即可满足单用户场景。

---

### 6. 定时同步窗口（Cron 式调度）

**现状**：`pollIntervalMs` 固定间隔轮询，无法表达「工作时间内每 5min，夜间每小时」这类策略；watcher 和 event channel 则始终活跃。

**用户价值**：减少低峰期的无效 API 调用（飞书 API 有配额），避免深夜打扰。

**建议实现**：
- 根配置增加可选 `syncWindow?: { start: string; end: string; timezone: string }` 字段；
- `SyncRuntime.scanAndSync()` 开始前检查是否在窗口外，超出时跳过轮询（watcher/event 仍响应，因为用户主动编辑应该同步）；
- 设置页提供「低功率模式」开关，自动启用窗口（23:00–07:00 不轮询）。

---

### 7. 同步摘要报告（每日/每周）

**现状**：历史视图展示原始操作记录，但没有汇总统计；用户难以了解「今天同步了什么」。

**用户价值**：让同步服务从「黑盒」变为「可信伴侣」，适合有审计需求的团队用户。

**建议实现**：
- 维护定时任务结束时生成当日汇总（push 了几条、pull 了几条、有几个冲突、失败几个）；
- Notifier 扩展 `category: "summary"` 事件类型；
- 仪表盘新增「今日同步摘要」卡片；
- 支持通过 Webhook 推送日报（与 P0-1 复用通知渠道）。

---

### 8. 配置备份与迁移

**现状**：全局配置在 `~/.feishu-sync-docs/`（含 token），每根的元数据在 `.feishu-sync/`。重装系统或换机器后需要重新配置所有根目录和凭证。

**用户价值**：降低环境迁移成本。

**建议实现**：
- 设置页新增「导出配置」按钮，下载脱敏 JSON（不含明文 token，token 可选包含）；
- 「导入配置」上传同格式文件，重建 roots 列表并提示逐个重新授权；
- `.feishu-sync/` 目录的 bindings.json 支持通过 API 导出（方便 debug 和手动恢复）。

---

## P2 — 体验优化

### 9. 暗色模式跟随系统

**现状**：Web 工作台有完整 CSS，但不确定是否有 `prefers-color-scheme` 媒体查询适配（`styles.css` 需确认）。长期盯着文档同步服务页面的用户需要暗色模式。

**建议**：跟随系统 + 设置页独立切换；所有 component 用 CSS variable 适配主题。

---

### 10. 首次绑定时自动选择「以哪侧为准」

**现状**：绑定的第一个文件夹（本地有文件 + 远端有文件）会立即进入四级配对，内容相同的自动 noop，不同的直接 conflict。但用户可能希望「首次以本地为准覆盖远端」或「首次以远端为准覆盖本地」，现在没有这个选项。

**建议**：BindRootForm 新增初始化策略选项：
- 自动合并（当前行为）
- 本地优先（本地文件全量 push，远端同名不同内容文件软删除）
- 远端优先（清空本地，全量 pull）
- 只绑定不同步（pending 状态，等待用户逐个确认）

---

### 11. Markdown 渲染预览增强

**现状**：MarkdownPreview 用 markdown-it 渲染，禁用了内嵌 HTML。但文档中常见的外链图片（`![desc](https://...)`）没有懒加载处理，飞书文档特有的 `callout`、`bookmark` 等富文本 Block 降级为普通段落后样式丢失。

**建议**：
- 外部图片 `<img loading="lazy">`；
- 识别飞书特有结构（以 `>` 引用块 + emoji 开头的 callout），渲染为带颜色背景的提示框；
- 代码块增加语言标识与 copy button；
- 内链跳转支持（在预览中点击相对路径链接切换到对应文档的预览，而非浏览器导航）。

---

### 12. 移动端适配优化

**现状**：App.tsx 有 `TAB_LABELS` 移动 tab bar 常量，说明有移动端意识，但复杂布局（分栏冲突工作台、文件树+预览双栏）在窄屏下体验待验证。

**建议**：
- 冲突工作台在 < 768px 时改为 Tab 切换（LOCAL/REMOTE 全屏）；
- DocsView 文件树折叠为汉堡菜单；
- 任务中心和仪表盘优先做移动端优化（主要查看场景）。

---

### 13. 操作撤销（Undo）

**现状**：冲突解决、回滚、忽略等操作一旦执行就立刻持久化，没有撤销入口。误操作「全部采用本地覆盖远端」后无法快速回退。

**建议**：
- 冲突解决后提供 10s 内「撤销」按钮，调用 `restoreBase()` 恢复基线内容并重新触发 sync；
- 忽略操作可立即 un-ignore（当前需通过 API 操作，UI 中入口不明显）；
- 回滚操作后广播一个 `rollback-undoable` 事件，提供「撤销回滚」。

---

## P3 — 长期演进方向

### 14. 多远端支持

当前架构通过 `RemoteProvider` 接口抽象，理论上可扩展到 Notion、Confluence、Google Docs 等，但 UI 与凭证管理目前为飞书单租户硬编码。

### 15. 多人协作（Server 模式）

现为单用户本地部署。如需团队共享：
- 增加认证层（OIDC/OAuth2 server）；
- 将 JSON 元数据替换为数据库（SQLite/PostgreSQL）；
- per-user roots + 共享 roots；
- 冲突通知推送到对应贡献者而非管理员。

### 16. 内容感知的语义合并

当前 Block 级合并对「两侧都修改同一段落」直接报冲突。长期可考虑接入 LLM 做语义级合并建议（展示为「merged」选项的预填内容），降低用户裁决负担。

### 17. 飞书文档评论/批注同步

飞书文档的评论（`docx/v1/document_blocks/comments`）是团队协作的核心，目前完全不在同步范围内。可以考虑将评论导出为 Markdown 附录（`<!-- comment: xxx -->`）或独立 `.comments.yaml` 文件。

### 18. 非文本文件同步

当前只同步 `.md` + 图片。PDF、Word、Excel 等二进制文件可通过 `uploadAsset`/`downloadAsset` 通道支持，需要：
- 扩展 `FilesystemProvider` 的白名单；
- 远端映射到 drive file（非 docx）；
- 合并策略：二进制文件无法三方合并，改为 last-write-wins + 冲突记录。
